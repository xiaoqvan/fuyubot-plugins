该消息里的文字**不是普通文字**：它用 Telegram 自定义 emoji（custom emoji）当字，
每个自定义 emoji 是一张贴纸图案。

输入 JSON 的 customEmoji 字段给出：出现了几次（count）、最长连排了几个（run）、
几种（unique）、是否像「用 emoji 当字」的图案（glyph_art）、出现过的 id，以及所属 emoji 集的标题（sets）。
能走到这一步，通常是因为**整条消息只有 emoji**：连续 5 个以上排在一起，没有任何别的文字。
message 字段里，每个自定义 emoji 已被替换成占位符 [E1]、[E2]……，编号就是联系表里的顺序。

图片（若附带）是这条消息里所有自定义 emoji 拼成的**联系表**：
- 白底，按阅读顺序排列，**行优先，每行两张**；
- 第 1 张对应 [E1]，第 2 张对应 [E2]，以此类推；
- 动画 emoji 取的是动画中段的静止帧，所以同一张图可能只显示图案的一部分，
  请结合上下文（尤其是 sets 里的集合名）判断。

判定要点：
1. 先把联系表里的图案**读出来**：它们是汉字、字母、数字、二维码、logo 还是表情？
   把读到的文字按顺序拼接，放进 Reason 里（用「图案内容: ...」开头）。
2. 如果拼出来的文字构成推广、招揽、联系方式（微信 / QQ / 电报 / 手机号）、
   交易、博彩、成人服务、代理 / 接单、引流到频道等，ad_detected = true。
3. 如果只是一组普通表情（说话带表情、表达情绪），或者图案读不出任何语义，
   ad_detected = false。
4. 集合名（sets）本身常常就是广告语或联系方式，看到「xxx代理」「加v」这类名字要加分。
5. 同一组 emoji 在不同群里反复出现、又读不出正常语义时，倾向判为广告（这是刷屏模板）。
